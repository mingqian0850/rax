## 3. 模型与任务输入

本机检测到 Codex CLI；这不等于 RAX 的模型认证已配置。仓库默认 OpenRouter，而本次 doctor 没有找到它默认位置的 key。可按 `rax/docs/SETUP.md` 第 4 节选择已有 API provider 或仓库支持的 ChatGPT 登录 profile。这里未读取、复制或写入你的凭据。

以下启动命令沿用默认 provider；若使用其他 profile，需要在启动时补上 `--profile <你的 profile>` 和必要的 `--provider-home`。使用仓库支持的其他 CLI 时，准备阶段也要匹配 `--agent-cli/--agent-provider`。保存准确模型 ID、CLI 版本、推理 effort 和输入条件，不把不同模型的结果混为同一复现。

LIBERO 的作者设置使用 3 张任务完成图，不把动作轨迹暴露给 agent。为 `libero_goal_1` 准备这些图：

本指南首轮使用 `--external-perception off`，省去外部 Gemini 接口依赖，使用 agent 自己的视觉能力；这是一个明确的简化设置，不等同于论文全部配置。如果暂不准备完成图，可用 `--demonstration-context none` 做流程试验，但必须在结果里标为无完成图实验。

## 4. A：在原场景探索，冻结后测原布局

建议先用 `libero_goal_1`，首轮 4 个探索 episode、5 个 formal 初态，确认全流程和日志产物。它是小样本试验，不能用 5 个初态的结果判断论文成绩。探索预算包含 rehearsal；4 次不保证足够学会任务。

```bash
RAX_CONFIG_A=$(runtime/envs/host/bin/python scripts/configure_auto_research.py \
  --task libero_goal_1 --sim-gpu 0 \
  --episodes 4 --exploration-start-seed 1 --exploration-collection 0 \
  --exploration-envs 1 --subagents 0 \
  --formal-eval-seed 1 --formal-seed 0 --formal-episodes 5 --formal-workers 1 \
  --agent-formal off --demonstration-context terminal_state \
  --external-perception off)
printf '%s\n' "$RAX_CONFIG_A"
```

这一步只写配置，不调用模型；当前驱动错误会阻止它完成，因为配置脚本也查询 `nvidia-smi`。不要伪造 GPU 查询来绕过。

确认上一步成功且输出了真实路径后启动：

```bash
bash scripts/start_auto_research_agent.sh --config "$RAX_CONFIG_A" --non-interactive
RAX_SESSION_A=$(dirname "$RAX_CONFIG_A")
```

从启动阶段开始会调用模型。episode 数是机器人尝试次数，不是 API 费用上限。首轮记录耗时与调用账单后，再决定扩展预算。

查看 `agent.log`、`agent-workspace/code/`、`agent-workspace/memory/`、`state.json` 和 formal 报告。若没有产出被接受的 bundle，先看失败原因，不要给它填一个成功率 0% 后和正常任务失败混淆。

## 5. B：原程序直接测交换布局

在 A 正常结束并完成 code formal 后读取所测 bundle 的 ID：

```bash
RAX_BUNDLE_A=$(runtime/envs/host/bin/python -c \
  'import json,sys; print(json.load(open(sys.argv[1]))["formal_batch"]["bundle"])' \
  "$RAX_SESSION_A/state.json")
RAX_SWAP_OUT="runtime/auto-research/local-swap-before-$(date -u +%Y%m%dT%H%M%S)"

  --source-session "$RAX_SESSION_A" --bundle "$RAX_BUNDLE_A" \
```

这里测试的是原 bundle 的场景泛化，不追加探索，也不调用模型。保留同一个 bundle 的哈希与具体初态编号。正式比较时将 A/B 的 formal 数量都扩展到 50；不要只挑成功的初态。

C 从 A 的探索 checkpoint 导入，而不是从 B 的测试反馈学习。不要把 B 的逐例失败分析喂给 C，否则改变了验证协议。让 agent 在 collection 6 的独立探索布局中发现问题，再用 collection 2 测试修改后的程序。

## 8. 扩展为有说服力的试验

先跑通，再固定模型、完成图、感知设置、代码版本与数据版本，将 formal 扩到 50。探索预算可比较 4/8/16，使用独立会话；至少做几个独立探索种子，以区分 agent 随机性与效果。这里的预算是建议的本地实验设计，不是论文统一预算。

要验证“积累经验带来适配收益”，追加两个对照：同样 5 次交换布局探索但从零开始；以及只带代码、清空旧会话（`--adaptation-context clear --transfer-parts code`）。注意：只清空会话却保留 memory 不等于移除记忆。

每次记录：任务/collection/初态编号、探索种子、模型与 CLI、完成图和视觉设置、各版本 bundle 哈希、成功/任务失败/基础设施错误、实际探索次数、耗时与成本、程序 diff、修改原因。模板见 `实验记录模板.json`。

停止会话使用作者提供的命令：

```bash
bash scripts/stop_auto_research_agent.sh --config "$RAX_CONFIG_A"
```

需要从中断恢复时按 `docs/USAGE.md` 使用 `--resume`；不要手改旧会话配置后假装仍是同一个实验。collection 5 改变任务目标，需要 agent formal，本轮 code formal 不覆盖该设置。
