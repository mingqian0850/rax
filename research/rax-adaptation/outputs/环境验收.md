## 安装过程中做的本地修复

1. 主环境安装脚本需要 curl，但本机没有。用 Python 下载同一个固定版本 Miniforge 安装器，核验作者给出的 SHA256 后安装，再继续作者脚本。
2. `egl_probe` 初次构建因缺少 `make`、C/C++ 编译器失败。在本任务的模拟器 conda 环境内安装 make、gcc_linux-64、gxx_linux-64，并显式指定该环境的 CC/CXX 后，作者模拟器安装脚本完成。没有安装系统级编译器。失败与成功日志分别是 `simulator-env-setup.log`、`simulator-env-retry.log`。
3. 作者固定的旧版 PyTorch wheel 在本机 glibc 2.43 上导入失败：`libtorch_cpu.so: cannot enable executable stack`。检查发现该库 ELF 的 GNU_STACK 为 RWE。使用环境内 patchelf 0.19.3 的 `--clear-execstack` 清除执行标记；修改前备份在 `work/compat-backups/libtorch_cpu.so.original`。修改前后 SHA256、绝对路径和操作见 `torch-compat-patch.json`。之后 torch 张量计算、MuJoCo/robosuite/LIBERO 导入通过。这个修复改变了**安装包里的二进制元数据**，没有改 RAX 或 LIBERO 源码；重新安装 torch 后可能需要重做。该问题和处理方法可对照 [conda-forge PyTorch 维护仓库的问题记录](https://github.com/conda-forge/pytorch-cpu-feedstock/issues/350)。

复现第 3 项的命令（仅在同样报错且确认目标环境时使用）：

```bash
cd /home/mingqian/Documents/Codex/2026-11-05/https-github-com-robot-agent-exploration/rax
runtime/envs/libero_pro/bin/patchelf --clear-execstack \
  runtime/envs/libero_pro/lib/python3.8/site-packages/torch/lib/libtorch_cpu.so
```

## 数据核验

作者数据脚本下载了固定 Hugging Face revision 的 320 个文件，但打印 `unverified: 320`：该 revision 的 SHA256SUMS 没有覆盖对应名称。没有把脚本退出成功误记为哈希全部校验通过。

随后独立读取相同固定 revision 的 Hugging Face 文件树，按普通 Git blob SHA1 或 LFS SHA256 核对本地下载，320 个全部匹配。逐文件方法和结果在 `data-integrity.json`。这验证下载与指定版本一致，不证明 benchmark 标注本身正确。

另用实际 PyTorch 读取 `libero_goal_1` 的 collection 1–5 初态，每组均有 50 个初态且数值有限，见 `libero-init-data-check.json`。还没有回放生成任务完成图；这一步需要恢复 GPU。
