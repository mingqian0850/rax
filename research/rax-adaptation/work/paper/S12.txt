12 Exploration Budget of ASPIRE on LIBERO-Pro ASPIRE ( Lu et al., 2026 ) writes robot programs in CaP-X ( Fu et al., 2026 ) with Claude Code
and Claude Opus 4.6. Its programs call the CaP-X interfaces for perception, including
text-prompted segmentation and vision-language pointing, for grasp planning, including a
top-down grasp selector, for inverse kinematics, and for joint-space motion, and they may not
read the simulator’s ground-truth state. On LIBERO-Pro, the unit of development is a task under
one perturbation: each of the 30 tasks of the Spatial, Object, and Goal suites is developed
separately for the position and the task perturbation, giving 60 programs, each written for
its own perturbed suite. For each task and perturbation, ASPIRE executes an initial program on a debugging split of 15
environment seeds (51–65), where a seed fixes one instance of the task, including object
poses, distractors, and the initial state of the robot. After each execution, the coding agent
reads a trace of every primitive call, with its inputs, outputs, and return status, the camera
frames before and after the call, grasp candidates, object poses, and motion-planning results.
It diagnoses the failure, patches the program, and replays the debugging seeds, with at most
three replays per seed. On some tasks, an evolutionary search additionally proposes candidate programs per iteration, conditioned on the three best programs and their failure
traces, and executes each candidate on the debugging split; the reported searches run for up
to four iterations, and is not reported. The final program is executed once on a
validation split of 15 further seeds (66–80) and then evaluated on seeds 1–50. A coordinator
promotes validated repairs into a shared library of skills, each stored with its failure
signature, its condition of use, its repair strategy, and a code sketch, which later sessions
read as in-context guidance. With the same loop on Claude Opus 5, Kang et al. (2026) report
a median of 0.99 hours and 91 thousand output tokens per task and perturbation. The debugging and validation seeds index instances of the same perturbed suite as the
evaluation seeds, so every rollout before the final evaluation is drawn from the distribution
on which the program is evaluated. This is also required by the task perturbation, which
changes the goal of the task: a program developed on the original task would pursue the
original goal. ASPIRE’s result on the Long suite comes from a separate setting, in which a
skill library built on the 90 tasks of LIBERO-90 is applied to the Long tasks without any
debugging on them. ASPIRE does not report the total number of rollouts per task; Table 20 gives the budget that its protocol implies, alongside that of RAX.
