3 The RAX Cognitive Architecture Inspired by Sutton’s OaK architecture ( Sutton et al., 2022 ) , RAX acquires all task-specific knowledge
at runtime from the agent’s own experience. Building on task-agnostic robot control interfaces and low-level controllers, the agent autonomously develops task-specific perception, manipulation strategies, and executable skills through exploration. The following modules surround the language-model core: perception and control , autonomous robot program , and memory for continual learning ( Figure 2 ). Figure 2 : System architecture and self-improving loop of RAX. The coding agent, powered by a frozen LLM, interacts with physical hardware across an isolation boundary using multimodal perception and control SDK interfaces. By reflecting on execution outcomes, the agent continually updates a persistent memory system containing working context, task notes, and a versioned repository of verified skills. During exploration, the agent compiles its perception and planning logic into standalone Python control programs that execute high-frequency loops directly on the robot. When encountering perception or planning failures due to environment variations, the program raises an exception ( raise Unsure() ), delegating control back to the agent to make adjustments and refine the codebase. 3.1 Multimodal Perception To build a physically accurate model of the world, we equip the agent with multimodal sensory inputs, including RGB images, depth maps, camera parameters, and force signals. The agent can thus construct 3D world models using depth data while regulating contact via force feedback. Notably, the 3D perception and object model fitting behaviors completely emerges from the agent exploration process, while we provide no skills, instructions or examples regarding specific usage of these multimodal sensing signals. A real-robot task illustrates this process: opening an air fryer’s drawer, placing a banana in its basket, and closing the drawer ( Figure 3 ). The agent lifts RGB-D observations into a point cloud in the robot’s base frame and constructs a geometric model of the fryer from its own measurements, localizing it in each new scene layout by fitting the fryer’s axis and handle direction with robust estimators. Because the drawer moves, the model is articulated, consisting of a fixed body and a drawer that slides along a prismatic joint. The agent plans every action, including grasping, pulling, and releasing, on this model and checks each motion for collisions. Section 14.2.1 details the model, the estimators, and how the program uses them. On a humanoid, the same process yields a gravity-aligned frame from the floor plane, landmarks for self-localization, and tracking updates after every gait cycle. As the interface between the agent and the physical robot,
we expose the robot’s control SDK as MCP tools, together with helpers such as an inverse
kinematics (IK) solver and the robot’s URDF model. With these tools, the agent plans each motion
and searches for feasible trajectories, accounting for the robot’s posture, collisions, and
joint limits. In the air fryer task ( Section 14.2 ), the drawer’s handle has a short horizontal arm on top and
a grip hanging down from its end. Grasping the grip from the front, as a person would, leaves
the arm almost no joint margin near its base for the pull, so the agent grasps the short arm from
above and pulls the drawer open in 3 cm steps (actions 1 and 2 in Figure 3 (b)).
The 18 cm banana barely fits the 19 cm basket: released from a level hand, it touched the top
of the fryer, and the opening fingers would hit the fryer’s body. The agent therefore tilts the
hand by about the banana’s axis, with the banana’s concave side toward the fryer, and
releases it with its middle just beyond the basket’s center (action 3). The agent found these
motions itself, by searching through the control tools during exploration, without human advice
or demonstrations; Figure 27 shows them on the real robot. 3.3 From Exploration to Autonomous Robot Program Generating each action with LLM-reasoning is expensive and slow. To enable high-frequency close-loop planning, the agent automates the decision process into a autonomous robot program with code that can directly execute to complete the task. Unlike prior work on coding agents for robotics ( Lu et al., 2026 ; Xiao et al., 2026 ) , we do not rely on hand-designed primitive skills or train policies by imitating human demonstrations, which inherently restricts scaling beyond human capability ( Sutton, 2019 ) . Instead, RAX agents directly control the robot without pre-trained policies or hand-coded primitives, progressively transferring control from high-level deliberation to autonomous code programs, resulting in autonomous decision-making through agent-native coding . Initially, the agent controls the robot through tool calls while perceiving the scene via the core LLM. Upon achieving task success, it compiles these decisions into code programs that run independently of main-agent deliberation. For example, after identifying object shapes and geometries, the agent generates a 3D object model and automatically estimates its position and pose using depth-derived point clouds when encountering new layouts. This eliminates the need for the main agent to repeatedly perceive and process raw images, which is slow and costly. The agent decomposes tasks into stages and implements modular skills with programs that check preconditions, execute motions, and verify outcomes, operating much like a software development process through testing, debugging, and code versioning. Empirical measurements from exploration, such as gait-cycle distance or reliable grasp orientation, become program parameters. The agent tests successive code versions during exploration and uses stage-level failures to identify which specific skill requires revision. The hammer-delivery program on the HumanoidArena DoubleDesk task ( Section 11.3 ), for instance, decouples approach, grasp, transit, obstacle crossing, and placement so that every failure traces directly to a specific stage ( Figure 20 ). Once reliable, the program is tested unattended in a new scene with exception handling and agent monitoring the generated logs in case of emergency situations. If perception or planning fails due to significant open-world variations, the program throws an exception, enabling the agent to step in, perceive the environment, and make necessary adjustments. Through scaled program testing and debugging during exploration, the result is a fully automated program that perceives, decides, and acts in unseen scenes with minimal or no agent intervention. Automated perception and planning allow it to adapt to new layouts in ways that replayed trajectories cannot. Deployment thus spans a continuum from the agent acting alone to a fully automated program, along which the agent advances as it accumulates experience. 3.4 Continual Learning with Memory As online experience scales and decision-making becomes automated, RAX continually expands its capabilities by constructing persistent memory systems for reuse across episodes and tasks. Persistent memory carries experience at multiple timescales ( Figure 2 , top). Within a session , notes
retain the current strategy, confirmed results, failed approaches, and useful parameters
through context compression, which lives in the agent scratch pad in workspace. Across sessions and tasks , a skill repository stores each skill with its code, the conditions under which it
applies, and evidence of its execution. It is continually contributed and merged by agents across different sessions and tasks, evolving with more experience. A skill enters the repository only after it executes successfully without supervision, together
with the evidence of that execution. Later sessions retrieve and compose skills that are
known to work instead of rediscovering the same behavior. The benefit is largest on real
robots, where every episode costs operator time: a grasp or a drawer-opening skill becomes a
building block for longer tasks, and each session leaves the library more capable than it
found it. Learning via Practice Much like humans, who repeatedly practice individual skills to gain proficiency before rehearsing complex, long-horizon tasks end-to-end, robot agents follow a similar cognitive progression. Here we depart from the conventional per-task training and evaluation protocol in robotics and frame robot learning as a continual process, where it generates and refines skills through practice and gradually moves on to more complex tasks by reusing the skills in the repository. Taking household tasks as an example, we let the agent practice individual subtasks, such as picking and placing (PnP) boxes and buckets or sorting tabletop items; each practice session is an exploration session on a single sub-task. During this process, the agent develops autonomous programs, rehearses them end-to-end to improve robustness, and eventually commits them to a multi-task skill library. During deployment on long-horizon compositional tasks, the agent reuses these subtask skills directly while verifying execution evidence and preconditions to handle environmental variations beyond those encountered during practice. Such skill acquisition and practice can also occur in parallel across multiple robots and tasks, enabling collective learning across multi-robot systems. 3.5 Parallel Multi-Agent and Multi-Environment Exploration Online exploration can be time-consuming due to the latency of agent reasoning and environment execution. To accelerate this process, we parallelize exploration across multiple agents and environments, enabling agents to evaluate distinct strategies concurrently rather than sequentially within a single environment. In our simulation experiments, leveraging parallel environments and agents reduces the wall-clock time required to reach target performance by more than , highlighting the scalability of parallelized exploration for robotic systems.
